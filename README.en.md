# Privernal Studio Web Frontend · privernal-platform-ui

[简体中文](./README.md) | English

The admin web frontend of Privernal Studio, carrying every building and operations surface of the low-code platform: a **form designer** (embedding the open-source PhoenixDesigner), **workflow orchestration** (warm-flow designer), reports & dashboards, a **big-screen dashboard designer**, document print templates, AI-assisted app building and Chat-BI, plus system administration (organization / permissions / dictionaries). Built with Vue 3 + TypeScript + Vite + Element Plus + UnoCSS + Pinia, organized as a pnpm workspace of shared internal packages; elegant-router file-based routing with backend-driven dynamic routes; bilingual UI (zh-CN / en-US); charts powered by ECharts, AntV G2/G6 and VisActor VChart/VTable.

Repository: <https://github.com/saperliu/privernal-platform-ui>
Backend service: `privernal-platform` (privernal-server)
Mobile app: `privernal-app`

## Tech Stack

| Area | Choice |
| --- | --- |
| Framework | Vue 3, `<script setup>`, TypeScript |
| Build | Vite (rolldown-vite), pnpm workspace |
| UI | Element Plus, UnoCSS, hand-drawn SVG icons |
| State | Pinia |
| Routing | Vue Router + elegant-router file-based routing (auto-generates `src/router/elegant/*`) |
| Requests | `@privernal/axios` (axios), `@privernal/alova` (alova, with local mock) |
| Charts | ECharts, AntV G2/G6, VisActor VChart/VTable |
| i18n | vue-i18n (`zh-cn` / `en-us`) |

## Requirements

- Node.js >= 20.19.0
- pnpm >= 8.7.0

## Quick Start

```bash
pnpm install

pnpm dev          # local development, loads .env.test
pnpm dev:prod     # start with .env.prod
pnpm build        # production build, output in dist/
pnpm build:test   # test-environment build
pnpm preview      # preview the built output
pnpm typecheck    # vue-tsc type check
pnpm lint         # ESLint autofix
```

Commits follow Conventional Commits; the bundled CLI can generate the message:

```bash
pnpm commit        # interactive commit message (English)
pnpm commit:zh     # interactive commit message (Chinese)
pnpm gen-route     # regenerate file-based routes
```

## Environment Variables

`.env` holds shared config; `.env.test` / `.env.prod` override the backend address.

| Variable | Description |
| --- | --- |
| `VITE_APP_TITLE` | Browser tab title; in-page titles come from the i18n key `system.title` |
| `VITE_STORAGE_PREFIX` | localStorage key prefix, currently `PRIVERNAL_` |
| `VITE_AUTH_ROUTE_MODE` | `static` for static routes / `dynamic` for backend-driven routes |
| `VITE_SERVICE_BASE_URL` | Backend address. test uses `http://localhost:7700/test`; prod uses `/api`, stripped by nginx on the deploy host and forwarded to backend port `8600` |
| `VITE_SERVICE_SUCCESS_CODE` | Business success code, must match the backend response envelope |

If the backend runs on its own domain, set `VITE_SERVICE_BASE_URL` to the full address and handle CORS.

## Directory Structure

```
├── build/                 # Vite plugins & proxy configuration
├── packages/              # workspace internal packages (@privernal/*)
│   ├── alova/  axios/  color/  hooks/  materials/  utils/
│   ├── scripts/           # in-repo CLI (bin: privernal)
│   └── uno-preset/        # UnoCSS shortcuts preset
├── src/
│   ├── assets/            # icons and static assets
│   ├── components/        # global components
│   ├── layouts/           # layouts and theme drawer
│   ├── locales/           # zh-CN / en-US copy
│   ├── router/            # routes (elegant/ is auto-generated, do not edit by hand)
│   ├── service/           # API layer
│   ├── service-alova/     # alova API layer with local mock
│   ├── store/             # Pinia stores
│   ├── theme/             # theme and layout defaults
│   ├── typings/           # type declarations (partially auto-generated)
│   └── views/             # pages
└── index.html
```

## Development Notes

- `src/router/elegant/*`, `src/typings/components.d.ts` and `src/typings/elegant-router.d.ts` are generated by build plugins — never edit them by hand.
- All UI copy goes through `src/locales/langs/*`; do not hardcode Chinese strings inside components.
- Demo pages (`src/views/plugin/*`, `src/views/function/*`, `src/views/alova/*`, `src/views/home/*`) are kept from the upstream template as component showcases; remove them as needed when productizing.
- The API layer still carries the template's example contracts; wiring login, dynamic routes and permission codes to the `privernal-platform` backend is tracked as its own work item.
